# 기준점 옮기기 (재도입) — 설계

2026-08-21 · 상태: 검토 대기

## 왜 다시 하나

사용자 말: *"지금 기준점을 옮길 수가 없어서, 아예 지도로써의 쓰임을 다 하지 못하고 있어."*

지금 중심은 창동씨드큐브 고정이다. `CENTER` 를 바꾸는 setter 가 코드에 없고,
거리는 수집기가 사무실 기준으로 미리 계산해 `restaurants.json` 에 박아둔
`distance_km` 을 그대로 쓴다. "나" 탭도 이걸 인정한다 — *"지금은 모두 여기 기준"*.

## 한 번 만들었다가 같은 날 뺐다

`7ca8f0ca` (2026-08-05) 에서 목록과 함께 들어왔고, `cef5e219` (같은 날) 에서 빠졌다.
제거 사유가 커밋에 남아 있다:

> Distance is already computed from the office, tapping the map to re-anchor was
> easy to trigger by accident, and browsing another neighbourhood is not what
> this app is for.

세 가지를 지금 기준으로 다시 판정하면:

| 당시 사유 | 지금 |
|---|---|
| 거리가 이미 사무실 기준으로 계산돼 있다 | **여전히 사실.** 기술적 비용이고 아래에서 다룬다 |
| 지도 탭이 실수로 너무 쉽게 눌렸다 | **여전히 유효.** 이 설계가 반드시 피해야 할 것 |
| 다른 동네 둘러보기는 이 앱의 목적이 아니다 | **반박됨.** 사용자가 그걸 원한다고 말했다 |

즉 되살리는 것 자체는 정당해졌지만, **2번을 피하지 못하면 같은 실수를 반복한다.**

## 무엇이 실수를 만들었나

예전 구현은 지도에 평범한 클릭 리스너를 달았다:

```ts
window.kakao.maps.event.addListener(map, "click", (e) => {
  onPickOriginRef.current({ lat: e.latLng.getLat(), lng: e.latLng.getLng() });
});
```

**탭 한 번에 기준점이 옮겨간다.** 바텀시트를 닫으려고 지도를 누르는 건 자연스러운
동작인데, 그게 그대로 기준점 이동이 됐다. 되돌리려면 리셋을 눌러야 하고,
그 사이에 목록과 반경 원이 전부 바뀌어 있다. **실수의 대가가 크고 즉시 눈에 띈다.**

## 채택: 지도를 옮긴 뒤 버튼을 누른다

지도를 팬해서 보고 싶은 곳으로 옮긴 다음, 떠 있는 버튼을 눌러 **그때의 지도 중심**을
기준점으로 삼는다. 국내 지도·배달 앱이 쓰는 "이 지역 검색" 패턴이다.

```
지도를 옮긴다  →  [ 🔍 이 지도 중심에서 찾기 ]  →  기준점 이동
```

- **오발 사고가 원리상 없다.** 기준점은 버튼을 눌러야만 움직인다.
  시트를 닫으려고 지도를 눌러도 아무 일이 없다
- **모드가 없다.** "고르는 중" 상태에 갇히지 않는다
- **발견 가능하다.** 지도를 옮기면 버튼이 나타난다 — 롱프레스처럼 숨어 있지 않다
- **팬 자체가 이미 의사표시다.** 다른 동네를 보려고 지도를 옮긴 사람에게
  "여기로 할래?"를 묻는 것이라 맥락이 맞는다

버튼은 **지도 중심이 현재 기준점에서 일정 거리 이상 떨어졌을 때만** 나타난다.
제자리에서 흔들린 정도로 뜨면 잡음이 된다. 문턱은 화면 대각선의 1/4 정도로 두되
구현 중 실측으로 조정한다.

돌아오는 길은 **이미 있는 「🏢 회사」 버튼**이다. 지금은 지도만 되돌리는데,
기준점도 같이 되돌리게 바꾼다. 새 컨트롤을 만들지 않는다.

### 버린 안

**롱프레스** — 오발은 막지만 아무도 발견하지 못한다. 지도 위 롱프레스는
브라우저의 컨텍스트 메뉴·텍스트 선택과도 부딪힌다.

**기준점 핀 드래그** — 지도에서 드래그는 팬이다. 핀을 정확히 집어야 하는데
그 핀이 14px이었던 게 오늘 고친 문제다([[04-지도와 목록]] 참조).

**모드 버튼 후 탭** — "여기서 찾기"를 누르면 다음 탭이 기준점이 되는 방식.
오발은 막지만 **모드에 갇힌다** — 지도를 좀 더 보다가 마음이 바뀌면
모드를 어떻게 빠져나가는지가 또 학습 대상이 된다.

## 데이터가 사무실 5km 안에만 있다

**이 설계에서 제일 중요한 제약이고, 예전 구현은 이걸 다루지 않았다.**

`restaurants.json` 은 창동씨드큐브 반경 5km 안만 담는다. 기준점을 3km 옮기면
새 기준점 주변 5km 중 상당 부분이 **우리가 데이터를 가진 적 없는 영역**이다.
지도는 그냥 비어 보인다 — "그 동네엔 비플페이 가게가 없다"로 읽힌다.
**없는 게 아니라 안 가져온 것이다. 조용한 거짓말이다.**

대응 두 가지를 같이 쓴다:

1. **수집 경계를 그린다.** 기준점이 사무실이 아닐 때, 사무실 중심 5km 원을
   옅은 점선으로 함께 그린다. 밖은 비어 있는 게 아니라 모르는 곳이라는 걸 눈으로 보여준다
2. **문구로 밝힌다.** 기준점이 사무실에서 멀 때 목록 위에
   *"여기서 멀어질수록 저희가 모르는 가게가 있어요"* 를 띄운다

기준점 이동 거리를 제한하지는 않는다. 막으면 왜 막히는지 설명할 자리가 또 필요하고,
경계를 보여주는 쪽이 정직하다.

## 거리를 다시 계산해야 한다

`distance_km` 은 사무실 기준으로 구워져 있다. 기준점이 움직이면 **화면에 쓰이는
거리는 전부 파생값이어야 한다.**

`lib/geo.ts` 의 `haversineKm` 이 이미 있다. 프로덕션에서는 아무도 안 쓰고
테스트만 쓰는데, **그 테스트가 5,782개 구운 거리값을 검증하는 장치**라
정확도는 이미 보증돼 있다. 그대로 쓴다.

5,782회 계산은 기준점이 바뀔 때마다 1회, `useMemo` 로 묶으면 체감되지 않는다.

### 고쳐야 할 소비처

| 어디 | 지금 | 바뀔 것 |
|---|---|---|
| `MapApp` 반경 필터 | `r.distance_km <= maxDist` | 파생 거리 |
| `MapApp` 정렬 | `place.distance_km` | 파생 거리 |
| `PlaceList` 줄의 거리 | `ListedPlace.distanceKm` | **이미 파생 모양이다** — 값만 바뀐다 |
| `PlaceList` "나" 탭 저장 목록 | `place.distance_km` | 파생 거리 |
| `RoulettePanel` 랜덤 후보 | `r.distance_km <= RANDOM_RADIUS_KM` | 파생 거리 |
| `MapView` 반경 원 | `CENTER` | `origin` |

`ListedPlace` 가 `{ place, distanceKm }` 로 이미 갈라져 있는 건 우연이 아니다 —
목록이 기준점 이동과 **같은 커밋에서 태어났기 때문**이다(`7ca8f0ca`).
그 모양이 남아 있어 목록 쪽은 손댈 게 거의 없다.

**`restaurants.json` 의 `distance_km` 은 남긴다.** 첫 화면(기준점 = 사무실)에서
5,782회 계산을 건너뛰는 값이고, 수집기가 채우는 필드다.

## 기준점은 저장하지 않는다

새로고침하면 사무실로 돌아온다. URL 에도 담지 않는다.

이 앱의 전제는 "회사 근처 점심"이고, 어제 노원구를 보다 닫은 사람이 오늘 아침
그 상태로 열면 **왜 이런지 알 수 없다.** 공유 링크(`/ladder/<token>`)에 기준점을
얹는 것도 마찬가지 — 받는 쪽에는 남의 기준점일 뿐이다.

## 「나」 탭 문구

지금 *"지금은 모두 여기 기준"* 이라고 적혀 있다. 이건 **기능이 없다는 고백**이라
이 작업으로 사라져야 한다. 현재 기준점 이름과 되돌리기를 그 자리에 둔다.

## 검증

- `haversineKm` 파생 거리가 기준점 = 사무실일 때 `distance_km` 과 일치하는지
  (이미 있는 테스트가 이걸 한다 — 회귀 방지로 계속 돌린다)
- 반경 원, 필터, 정렬, 룰렛 후보가 **한 기준점을 본다** — 하나만 안 따라가면
  "1km 안"이 화면마다 다른 뜻이 된다
- 시트를 닫으려 지도를 눌렀을 때 기준점이 **안 움직인다** (제거 사유 2번의 회귀 테스트)
- 사무실에서 먼 기준점에서 수집 경계 원과 안내 문구가 보인다

## 범위 밖

- 현위치(GPS) 기준 — 별개 기능이고 권한 흐름이 붙는다
- 수집 반경 확대 — 기준점을 옮겨도 데이터가 안 따라오는 문제의 근본 해결이지만
  수집기 쪽 일이고 몇 시간짜리 재수집이 붙는다
- 목록과 상세가 한 자리를 다투는 문제 — 관련은 있으나 독립적이다
